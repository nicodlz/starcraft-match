# 0x00401D40

The independently authored C candidate compiles to **26 bytes**, compared with
**27 original bytes**; it is **not an exact match** under either existing Clang
profile. No original-process or differential execution was performed.

## Pinned observation and boundaries

SHA-256: `ad6b58b27b8948845ccfa69bcfcc1b10d6aa7a27a371ee3e61453925288c6a46`.
Fresh PE extraction was inspected at entry, through both returns, and across the
surrounding boundaries. The contiguous body is `[0x00401D40, 0x00401D5B)`;
returns occur at `0x00401D57` and `0x00401D5A`. The preceding routine returns at
`0x00401D3C`; intervening bytes and `0x00401D5B` through `0x00401D5F` are
breakpoint padding. The next routine starts at `0x00401D60`.

Entry is independently corroborated by direct calls at `0x00431A8B`,
`0x00476EAB`, and `0x0049AC80`, rather than inferred from padding alone.
Each inspected caller puts its pointer in EAX and tests the full EAX result after
the call. These call sites provide no stack argument or associated cleanup.
The callee modifies EAX and flags, with no observed use of other registers.

## Reconstructed behavior and ABI

The candidate uses i386 `regparm(1)` to express the observed EAX pointer argument
and returns an unsigned integer in EAX. A null pointer returns zero. Otherwise,
it reads an unsigned 16-bit index at pointer offset `0x64`, tests bit `0x10` in
the byte at `0x00664080 + index * 4`, and returns exactly zero or one. There is
no observed index range check. The candidate preserves the byte access width;
its minimal layout asserts the index offset. Field and global meanings remain
unassigned hypotheses; no community semantic name or implementation was used.

## Compilation and remaining difference

`src/game/sub_00401D40.c` is built with `clang-i686-scaffold` (`-O2`) for the
proposed record; `clang-i686-size` (`-Oz`) was also measured. Both produce the
same 26-byte body. The strict isolated COFF extraction accepted the whole
function section with no relocations. Comparison includes the complete original
27-byte region and the complete candidate section without normalization.

The original tests the indexed byte and branches to a shared zero return; its
true path loads the constant one. Clang instead loads the byte, shifts it right
by four, and masks it with one. Consequently the null-path jump displacement
also differs. Three private branch-likelihood source experiments did not change
this result and are not part of the public candidate.

The pointer and return ABI and accessed widths are observed, but runtime behavior
has not been tested in the original process. Instruction, CFG, and semantic
comparison metrics remain null. Modern Clang compilation does not establish
historical compiler identity. The coordinator must independently rebuild and
review the proposed record before catalog integration.
