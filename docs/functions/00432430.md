## Observed behavior and ABI

EAX supplies a non-null object pointer, ECX supplies an index. The body reads
a 32-bit pointer at object offset `0x134`. If that pointer is null, or its byte
at offset `8` is not `3`, it returns without stores. Otherwise it clears the
byte at pointer offset `9 + index`, then writes a zero DWORD at offset
`0x18 + 4 * index`. There is no index bounds check. EDX is zeroed on every path;
EAX contains the loaded pointer at return. The inspected caller ignores both.
No semantic field names or community annotation are asserted.

The independently authored C candidate uses Clang `regcall` to represent the
EAX/ECX inputs. Its abstract result is void because the reviewed caller does not
consume the returned registers. The original's EDX-zero side effect is not
explicitly reproduced by the C calling convention; full incoming-reference and
register-liveness audits remain open.

## Measured result

Clang 18.1.3 with recorded `clang-i686-scaffold` produces **30 bytes**, with no
COFF relocations, against the full 27-byte original region. It does **not** match.
Clang uses a pointer self-test and immediate zero stores; the original zeros EDX,
compares the pointer with EDX and reuses EDX for both stores. The source preserves
the original byte-store then DWORD-store sequence under this measured profile.

The recorded `clang-i686-size` experiment produced 27 bytes but also mismatched;
it used a read-modify-write DWORD operation for the second store. That profile
is not selected because it introduces an extra memory read.

Private reports were generated with `tools.analysis.pe.PE.region`,
`tools.matching.compare.coff_function` and `compare`. Whole isolated sections were
compared without trimming, relocation handling or byte normalization. No original
execution or semantic differential test was performed. Coordinator review,
recompilation and catalog integration are pending.
