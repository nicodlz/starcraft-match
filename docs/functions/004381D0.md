## Observed behavior and ABI

The body reads a DWORD pointer at object offset `0x134`. It returns zero if
that pointer is null, its byte at offset `8` is not `4`, or its DWORD pointer
at offset `0x0C` does not equal the input object. Otherwise it reads the
object's WORD at offset `0x64`, uses that value to index a byte at
`0x00664080 + 4 * value`, and returns one if that byte's bit zero is clear,
zero otherwise. The byte table access remains a byte access despite its stride
of four. There are no writes or bounds checks. The input object must be non-null.

The candidate expresses the ECX input with genuine `__fastcall`; its unsigned
integer result supplies a full DWORD in EAX. Original and candidate change EAX,
may change ECX and DL, and preserve the upper EDX bits and remaining general
registers. They also change flags. All paths use a plain return.

## Matching evidence and limitations

The independently written C uses a compound condition to preserve the conditional
access order. MSVC emitted an isolated 44-byte COMDAT function with no relocations.
`coff_function` extracted its entire section and `compare` compared it literally
with `PE.region(0x004381D0, 44)`. No bytes, instructions or padding were inserted,
trimmed, normalized or patched. The private fresh report records source and
compiler-component hashes, driver identity and full flags.

Separate early-return source produced a different branch layout and final bit
computation. The compound form matches with both recorded MSVC profiles; the
selected profile is `msvc71-o2`. Modern Clang variants did not reproduce all
44 bytes. This does not establish a complete historical toolchain reconstruction,
linked-game build or original-process differential execution. The broader semantic
meaning of the indexed data remains a community hypothesis.
