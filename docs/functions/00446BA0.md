## Observed accesses and ABI

It reads one byte at `0x006900FB + index * 0x4E8`, then clears bit 3 of the byte
at `0x00690101 + index * 0x4E8` through a byte read-modify-write. If the first
byte was nonzero, it writes that byte minus one back to its original location.
There is no bounds check. The order of reads and writes is preserved by volatile
byte accesses in the independently authored candidate.

The return is plain `ret`, with no stack arguments. EAX and CL are changed;
upper ECX bits and other general registers are preserved. Flags change. The
inspected caller ignores EAX/ECX after the call. `regparm(1)` supplies the observed
EAX input; literal equality establishes the same register effects in this build.
No semantic state layout is asserted beyond these measured addresses and widths.

## Validation and limits

The entire isolated COFF function was extracted with `coff_function`, which rejects
relocations, and compared with `PE.region(0x00446BA0, 32)` using the repository's
literal-byte comparator. No bytes were trimmed, normalized or patched. The final
public source was recompiled after installation, and equality was measured again.
The `clang-i686-scaffold` experiment produced 33 bytes due to a zero-extending
byte load; it was not selected.

This is an isolated function match, not full-program linking or original-process
differential execution. The community annotation's semantics remain unverified;
index bounds and broader calling-context assumptions remain unknown.
