# sub_00446D40

The independently written C candidate compiles to **33 bytes**, versus the full
reviewed **25-byte** original region. The current comparison is **not exact**.

## Pinned binary evidence

All observations refer to the executable SHA-256
`ad6b58b27b8948845ccfa69bcfcc1b10d6aa7a27a371ee3e61453925288c6a46`.
Fresh PE extraction and disassembly cover entry `0x00446D40` through the final
return at `0x00446D58`; the other return is at `0x00446D54`.
Inspected `INT3` padding begins at `0x00446D59` and ends at `0x00446D5F`.
The preceding region returns at `0x00446D32` and has padding through
`0x00446D3F`. Padding is supporting evidence; the direct call below separately
corroborates the entry.

The direct call at `0x0045BE6E` targets this entry. Its preceding instructions
assign AL to CL at `0x0045BE69`, then load EAX from the DWORD at ESI offset
`0x10` at `0x0045BE6B`. No stack argument is passed, and the subsequent jump
does not consume a result. Only the low byte of ECX is initialized.

## Observed behavior and candidate ABI

EAX supplies an unsigned index and CL supplies a byte selector. The routine
computes `0x00690100 + index * 0x4E8` using wrapping 32-bit arithmetic, then
sets bit 7 of the byte there when CL is 4, or clears it otherwise. Every other
bit is retained. The original uses a byte memory read-modify-write in either
branch. It performs no bounds check and returns with a plain `RET`, without
stack cleanup. No semantic names for the index or data are asserted.

The candidate uses `regparm(3)` on i386, with an unused second argument as an
EDX carrier so the third argument reaches ECX. EDX is not an input to the
observed routine. The third argument is declared unsigned and explicitly
masked to its low eight bits; this avoids assuming the caller initializes the
upper ECX bits. The function has a void result because none is consumed in the
reviewed caller. The original leaves the calculated address in EAX; this
incidental register value is not represented as an authenticated return ABI.

## Measurement and uncertainty

Both recorded Clang profiles were tested across six source variants, for
12 bounded experiments. The final source uses `clang-i686-size` and strictly
extracts its complete isolated COFF function with no relocations. Clang folds
the two branches into a comparison, selector-bit calculation and separate
byte load/store, producing 33 bytes. The original branch layout and memory
read-modify-write instructions remain unmatched. The final source was rebuilt
after selection and compared across the entire 25-byte pinned region.

The proposed catalog record and fresh detailed report stay private under
`.local/batch20_run/`. The coordinator must independently rebuild before
integration. No original-process or differential execution was performed;
semantic, instruction-similarity and CFG scores remain null. These small Clang
experiments do not identify the original compiler.
