# sub_0047D160

The complete **1-byte** function matches independently authored pure C exactly
with `clang-i686-scaffold`. Strict isolated COFF extraction reports no relocations.

## Specimen and boundaries

These observations apply to Windows i386 1.16.1 SHA-256
`ad6b58b27b8948845ccfa69bcfcc1b10d6aa7a27a371ee3e61453925288c6a46`. The complete region is
`[0x0047D160, 0x0047D161)`, including its final return.

The body is a single RET at `0x0047D160`. The preceding routine returns at
`0x0047D150`; intervening INT3 padding reaches `0x0047D15F`. Trailing INT3
padding runs from `0x0047D161` through `0x0047D16F`. Direct call
`0x004D98EC` independently corroborates the entry. This is an observed no-op
leaf in the game loop, rather than a forwarding thunk.

The pinned [BWAPI map](https://github.com/bwapi/bwapi/blob/d727fed68558c506163048ea889131d8cbb33915/Release_Binary/Starcraft/bwapi-data/data/Broodwar.map) independently corroborates entry and size under
community annotation `nullsub_gameloop`; this is not an original symbol.

## ABI and validation

No observable arguments, memory access, or return value. Plain RET preserves
all general-purpose registers and stack position. The inspected caller calls
`0x0047D160` without pushing arguments and immediately calls `0x0047F590`
afterward; it does not consume a result. The empty C body emits the same RET.

The source is `src/game/sub_0047D160.c`. The experiment rebuilds with the
recorded profile, uses `PE.region`, `coff_function`, and `compare` across the
entire original region and isolated candidate section, and rejects relocations.
No byte normalization or trimming was performed. Private reports remain under
`.local/hundred/0047D160/`.  No original-process or differential execution was performed.
