plain return with caller cleanup. The emitted REP operations retain the normal
forward-copy direction assumption; no additional direction-flag handling is
introduced.

## Observed behavior and reconstruction

The function reads context DWORD offset `0x10`, then the requested DWORD, then
context position DWORD offset `0x04`. It subtracts the position with unsigned
32-bit wraparound and selects the unsigned minimum of that difference and the
requested value. Context offset zero is the source base pointer. It copies
`count / 4` DWORDs followed by `count % 4` BYTEs from base plus position to the
destination. It rereads the position after copying, adds the copied count with
32-bit wraparound, stores the updated position, and returns the count. No range,
null or underflow checks are added; fields `0x08` and `0x0C` remain unassigned.

The [independently written C90 candidate](../../src/game/sub_004C3090.c) uses
volatile views for the first two reads to preserve their order and an explicitly
declared compiler `memcpy` intrinsic only for native MSVC (`_MSC_VER` without
`__clang__`). No library implementation was copied. The intrinsic emits the exact
original DWORD-then-BYTE progression without calls or relocations. The portable
branch independently expresses that forward progression with volatile, unaligned
DWORD views and BYTE accesses; it does not call a library copy routine. Strict
Clang COFF extraction accepts the same `_sub_004C3090` symbol with zero section
relocations. That branch is a source portability check, not an exact match or
original differential-execution claim. The post-copy context read is preserved
in the exact native emitted code.
