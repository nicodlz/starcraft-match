## Entry reference and observed ABI

At `0x004D3F2A`, the pinned executable pushes this function pointer, then pushes
identifier 3 and calls `0x00410100` at `0x004D3F31`. That thunk jumps through
IAT slot `0x004FE3CC`, imported from `storm.dll` by ordinal 123. This is observed
callback registration evidence, independent of the boundary padding.

The callee itself reads a single DWORD stack pointer at `[EBP+8]`, restores its
EBP frame, and executes `ret 4`. EAX, ECX and EDX are scratch; all other general
registers are preserved. The candidate therefore expresses the observed callee
contract using one stack argument and `__stdcall`. The external Storm dispatcher
was not available for inspection: its argument preparation and return use have
not been independently established. Registration does not prove actual callback
execution or reachability. This remaining caller uncertainty is explicit in the
provisional record and requires coordinator review.

## Accesses and independent source

The function reads the DWORD index at pointer+4. If its unsigned value is at
least 8, it returns without storing. Otherwise it reads the DWORD value pointer
at +8; a null pointer or unsigned DWORD size at +12 below 4 selects value 3.
When both checks pass it reads one DWORD through the value pointer, replacing
zero with 3. It then stores the selected DWORD at `0x005971E4 + index*4`.
There is no null check on the incoming event pointer. No other memory is written.
The source uses a minimal four-DWORD layout and preserves the access order and
short-circuit checks. Semantic field names are descriptive hypotheses.
