# REA / Ghidra trial, 2026-10-04

**Four newly reconstructed functions / 144 original bytes match exactly.**
The four previously reviewed mismatches remain non-exact. The full fresh
proof verifies **415 functions / 25,155 bytes**, comprising 385 isolated COFF
matches and 30 standard-linked external-reference matches. Excluding these
four additions, that same proof covers 411 pre-existing exact entries /
25,011 bytes. The earlier README total of 253 did not include later catalog
batches; those additional entries are not results of this trial.

All observations concern the Windows i386 1.16.1 executable SHA-256
`ad6b58b27b8948845ccfa69bcfcc1b10d6aa7a27a371ee3e61453925288c6a46`.

Discovery used the existing private Ghidra export. Each selected region had
direct-call entry evidence; boundaries, returns, neighboring bytes, access
widths and callers were independently re-extracted from the pinned PE and
hand-reviewed. Fresh REA dossiers subsequently corroborated those observations.
The sources were independently written from binary observations, without
consulting community implementations or assigning semantic function names.

CL 13.10.3077 under the recorded wibo driver compiled the final public sources.
The coordinator then rebuilt each through `./tools/decomp match ADDRESS` and
inspected the fresh full-region report. All four whole isolated sections have
zero relocations and literal byte equality. The two EAX-input candidates use
ordinary static C plus an external optimizer context; those contexts are not
reconstructed or counted original functions. No shared compiler profile,
structure header, matcher or Ghidra exporter was changed for this trial.

The three existing historical profiles were tested for each new function.
The size profile matched none of the four. The frame profile is necessary
for `0x00401170`; the ordinary O2 profile suffices for the other three.
Explicit unsigned addition in `0x00401400` preserves the observed DWORD wrap
before the arithmetic shift, and was recompiled before the final comparison.

## REA setup and measurements

[REA upstream](https://github.com/morluto/rea) version **3.2.1** was installed
under ignored `.local/rea-trial/`, without adding a repository npm dependency
or changing global agent registrations. Its bundled native investigation guide
was read. The provider used the existing **Ghidra 12.1.4**, **Temurin JDK
21.0.12.1+1** and Node **26.3.1** on Ubuntu 24.04. REA accepted this PE32 x86
target and bound all successful dossiers to its exact SHA-256.

The CLI produced the `0x00401120` dossier. A retained session through REA's
packaged runtime produced the seven remaining dossiers and closed the provider
successfully. That retained batch took **119,189 ms** in total: its first dossier
took 118,805 ms including provider startup/analysis, and subsequent dossiers
took 12–29 ms each. This measures this batch only, without a comparative
benchmark against our existing exporter. The local Evidence IDs are recorded
in the eight function notes; full dossiers, snapshots and diagnostic logs stay
ignored.

A separate MCP trial connected and successfully opened the target, but its
first dossier request exceeded the client's 600,000 ms timeout. Its orphaned
Ghidra process later recorded 2,092 seconds of auto-analysis. The owned process
group was stopped and its private runtime removed after preserving diagnostic
logs locally. A duplicate one-shot request was cancelled before switching to
the successful retained batch. Interactive MCP readiness is therefore not
claimed; no permanent MCP registration was installed.

REA provides useful assembly, incoming references, CFG and decompiler context
in one provenance-bearing result. Default signatures can still omit the actual
ECX/EAX argument contract. It neither established those ABIs nor produced the
C-derived byte equality; caller review, historical compilation and the project's
strict matcher did. This trial supports further local use for investigation,
while the comparative productivity gain remains unmeasured.

Reproduce a one-shot dossier locally after installing the exact package:

```sh
npm install --prefix .local/rea-trial --no-audit --no-fund rea-agents@3.2.1
source .local/tools/activate.sh
export GHIDRA_INSTALL_DIR="$GHIDRA_HOME"
.local/rea-trial/node_modules/.bin/rea function original/StarCraft.exe 0x00401400 \
  --provider ghidra --snapshot analysis/rea-trial/example-snapshot.json \
  --format json > analysis/rea-trial/example-dossier.json
```

The activation file is host-local; a fresh clone must supply its own legally
obtained executable, Ghidra, JDK and historical compiler. REA's CLI invokes a
separate ephemeral analysis session per uncached command. The retained research
harness and experiment sources remain ignored rather than becoming supported
project tooling.

## Validation and limits

`make proof` freshly passed all **415 exact expectations / 25,155 bytes**,
including the four final public sources. After activating the explicit local
compiler paths, `make` compiled all **422 candidates** and passed **64 tests**,
including the private-checkout proof and deliberate source-regression rejection.
The initial unactivated test run failed because the temporary checkout could
not locate the historical compiler; no source correction was needed for that
failure. Each new source also compiled with
the existing portable Clang profile and passed strict isolated extraction
without relocations; its different emitted bytes are not original matches.

No original bytes, copied assembly, normalization, trimming or post-build patches
were used to obtain equality. No full-program link, original-process execution,
original differential test or playable game is established. Instruction, CFG
and semantic comparison metrics remain null.

The publication guard passed for tracked files and for all 16 public trial paths
through a temporary Git index. The real index was left untouched. Private REA
packages, game-derived dossiers, snapshots, compiler experiments and logs remain
ignored. At the end of the original trial, no commit or external upload had
been performed.
